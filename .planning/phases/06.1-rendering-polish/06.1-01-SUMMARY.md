# Phase 06.1 Plan 01: Critical Vulkan Bugs Summary

**Fix 4 critical Vulkan correctness bugs: depth store_op STORE, per-region scene_buffer grow copy, split mesh shader push constants, Hi-Z pass 0 1:1 copy mode**

## Performance

## Accomplishments
- Depth attachment store_op changed from DONT_CARE to STORE — Hi-Z pyramid now reads valid depth data on all GPU vendors
- scene_buffer grow_capacity uses 4 per-region BufferCopy entries with correct src/dst offsets — no data corruption after capacity growth
- Mesh shader push constants split into two calls (TASK_EXT [0..40) + MESH_EXT [48..128)) — Vulkan spec compliant, no validation errors
- Hi-Z pass 0 uses compute shader copy_mode=1 for 1:1 depth→hiz transfer — no out-of-bounds texel reads at equal resolution

## Decisions Made
- CRIT-07: Used shader copy_mode instead of vkCmdCopyImage because D32_SFLOAT→R32_SFLOAT cross-format copy isn't supported. The compute shader samples depth via combined image sampler and writes to hiz storage image.
- CRIT-02: Offsets must be computed per-capacity because align_up(16) produces different padding at different buffer sizes.
- CRIT-03: Combined TASK_EXT|MESH_EXT stage flags with a single push spanning the [40..48) gap is a spec violation, even though some drivers tolerate it.
