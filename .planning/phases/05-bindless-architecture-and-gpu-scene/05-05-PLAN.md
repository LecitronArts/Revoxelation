<objective>
Replace the fixed MAX_RENDER_CHUNKS=881 limit with dynamic capacity starting at
1024 slots. Implement 2× growth when utilization exceeds 90%. Switch from
vkCmdDrawIndexedIndirect to vkCmdDrawIndexedIndirectCount for GPU-driven draw
count management.
</objective>

<locked_decisions>
- D-01: Initial capacity: 1024 slots (replaces MAX_RENDER_CHUNKS=881).
- D-02: Growth trigger: `active_chunks > capacity * 0.9` (i.e., >921 for initial 1024).
- D-03: Growth factor: 2× (Vec-style doubling). New capacity = old capacity * 2.
- D-04: Growth flow (between frames, after fence wait for current frame):
  1. Allocate new buffers (vertex, index, scene) at 2× size.
  2. Record vkCmdCopyBuffer from old to new for all 3 buffers.
  3. Submit one-shot command buffer, fence wait.
  4. Destroy old buffers.
  5. Update BindlessTable descriptor bindings to point to new buffers.
  6. Expand SlotAllocator internal capacity (extend free_slots, etc.).
- D-05: Growth check happens at start of submit_frame, BEFORE command buffer recording.
- D-06: vkCmdDrawIndexedIndirectCount usage:
  - Draw count buffer: already exists (cull_pipeline.draw_count_buffer).
  - Replace `cmd_draw_indexed_indirect(cmd, dense_indirect, 0, draw_count, stride)` with `cmd_draw_indexed_indirect_count(cmd, dense_indirect, 0, draw_count_buffer, 0, max_draw_count, stride)`.
  - max_draw_count = current capacity (not active_draw_count).
  - Since drawIndirectCount is Vulkan 1.2 core (already required by Plan 01), no extension loader needed — use ash's core device function.
- D-07: The CPU-side `active_draw_count()` value is still passed to the cull shader dispatch (to know how many threads to launch), but the draw command reads the actual visible count from the GPU-written draw_count_buffer.
- D-08: SlotAllocator::grow(new_capacity):
  - Extend slot_to_chunk, slot_to_draw_index, metadata_shadow, indirect_shadow to new_capacity.
  - Add new free slots from old_capacity..new_capacity to free_slots.
  - chunk_to_slot and draw_index_to_slot don't need resizing (they grow dynamically).
- D-09: The mesh_pipeline.draw() call no longer receives a draw_count from CPU. Instead, it uses cmd_draw_indexed_indirect_count with the draw_count_buffer.
- D-10: For ash API: `device.cmd_draw_indexed_indirect_count(cmd, buffer, offset, count_buffer, count_offset, max_draw_count, stride)` — this is available on `ash::Device` when Vulkan 1.2 is the API version.
- D-11: Vertex shader is NOT modified in this plan. It continues using gl_InstanceIndex (= firstInstance = slot_id) as decided in Plan 05-03 D-04. IndirectCount is compatible with this approach because each dense indirect command's firstInstance field still carries the slot_id. gl_DrawID is not needed.
</locked_decisions>
</context>
