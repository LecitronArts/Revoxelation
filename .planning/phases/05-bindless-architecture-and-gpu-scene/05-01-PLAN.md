<objective>
Upgrade device selection to hard-require Vulkan 1.2 descriptor indexing and
drawIndirectCount features. Devices that lack any required feature are rejected
with a clear error message listing the specific missing features. No fallback.
</objective>

<context>
@src/renderer/device.rs
@src/renderer/instance.rs
@.planning/phases/05-bindless-architecture-and-gpu-scene/05-RESEARCH.md

Instance already requests apiVersion 1.3 (instance.rs line 85). Device creation
currently uses only VkPhysicalDeviceFeatures (1.0) without pNext chain. Must add
VkPhysicalDeviceVulkan12Features to both the feature probe and device creation.

<locked_decisions>
- D-01: Use `vk::PhysicalDeviceVulkan12Features` via pNext chain on `vk::DeviceCreateInfo`. Do NOT use the extension-era `VkPhysicalDeviceDescriptorIndexingFeatures` — use the core Vulkan 1.2 struct.
- D-02: Required Vulkan 1.2 features (all must be VK_TRUE):
  - `descriptor_indexing`
  - `shader_sampled_image_array_non_uniform_indexing`
  - `runtime_descriptor_array`
  - `descriptor_binding_partially_bound`
  - `descriptor_binding_sampled_image_update_after_bind`
  - `descriptor_binding_storage_buffer_update_after_bind`
  - `draw_indirect_count`
- D-03: Feature probe uses `instance.get_physical_device_features2()` with `VkPhysicalDeviceVulkan12Features` in pNext chain.
- D-04: Error message format: "Vulkan 1.2 feature(s) missing: {comma-separated list of missing feature names}. GPU: {device_name}."
- D-05: The existing Vulkan 1.0 features (samplerAnisotropy, multiDrawIndirect, drawIndirectFirstInstance) remain required alongside the new 1.2 features.
- D-06: `DeviceCreateInfo` uses `.push_next(&mut vulkan12_features)` instead of `.enabled_features()` for the 1.2 features. The 1.0 features go into a `VkPhysicalDeviceFeatures2` pNext chain as well, or via the `features` field of the Vulkan12 struct. Follow ash's builder pattern.
</locked_decisions>
</context>
