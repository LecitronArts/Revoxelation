<objective>
Implement Hi-Z (hierarchical-Z) occlusion culling: a depth pyramid generated from
the previous frame's depth buffer, sampled by the cull shader to reject chunks fully
occluded by nearer geometry. This builds on the frustum culling from 04-05 as a
second culling pass.
</objective>

<locked_decisions>
- D-01: Hi-Z image format: `R32_SFLOAT`. Full mip chain from `ceil(log2(max(width, height)))` levels.
- D-02: Hi-Z generation: compute shader `hiz_generate.comp` reads mip N-1 and writes mip N, using 2×2 max reduction. Dispatched once per mip level. First mip reads from the depth buffer itself.
- D-03: Hi-Z image lifecycle: created during swapchain creation, recreated on swapchain resize.
- D-04: Previous frame's depth: the cull shader samples the Hi-Z pyramid generated from the PREVIOUS frame's depth output. This is 1-frame latency, acceptable for voxels.
- D-05: Conservative test: project AABB to screen-space rect, determine the mip level where the rect covers ≤2×2 texels, sample the Hi-Z at that level. If the max depth in the rect is less than the AABB's minimum Z, the chunk is occluded.
- D-06: Inflate the projected screen-space rect by 1 texel in each direction to prevent popping from sub-pixel inaccuracy.
- D-07: Hi-Z culling is toggled via a uniform flag (e.g., in the frustum planes SSBO or a separate config UBO). Default: enabled. Runtime toggle for debugging.
- D-08: Hi-Z pyramid sampler: `VK_FILTER_NEAREST`, `VK_SAMPLER_REDUCTION_MODE_MAX` (VK_EXT_sampler_filter_minmax, core in Vulkan 1.2). Fallback: manual 4-sample max in shader if extension unavailable.
- D-09: The depth image already has SAMPLED usage flag from 04-04.
- D-10: build.rs must be updated to compile hiz_generate.comp.
</locked_decisions>
</context>
