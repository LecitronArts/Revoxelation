<objective>
Implement robust swapchain lifecycle management: recreation on window resize,
handling OUT_OF_DATE and SUBOPTIMAL errors, graceful minimization handling, and
proper destruction/recreation of dependent resources (depth image, framebuffers, image views).
</objective>

<locked_decisions>
- D-01: Swapchain recreation sequence: device_wait_idle → destroy framebuffers → destroy depth image/view → destroy old image views → create new swapchain (with old_swapchain param) → destroy old swapchain handle → create new image views → create new depth image → create new framebuffers.
- D-02: Render pass does NOT need recreation — format stays the same.
- D-03: Pipelines do NOT need recreation — they use dynamic viewport/scissor (from 04-02).
- D-04: Descriptor sets do NOT need recreation — they reference chunk pool buffers, not swapchain resources.
- D-05: On acquire_next_image returning OUT_OF_DATE, skip the frame and recreate immediately.
- D-06: On queue_present returning SUBOPTIMAL or OUT_OF_DATE, recreate after present completes.
- D-07: When window extent is 0×0 (minimized), skip rendering entirely. Don't attempt swapchain creation with zero extent.
- D-08: Store a `needs_resize: bool` flag and desired extent so recreation happens at the right time (before next acquire).
- D-09: egui_backend does not reference swapchain resources directly (it renders into the render pass), so it survives swapchain recreation unchanged.
</locked_decisions>
</context>
