<objective>
Migrate all 6 chunk pool buffers from CpuToGpu memory to GpuOnly memory with a
ring-buffer staging pipeline. Uploads happen via vkCmdCopyBuffer recorded into the
frame command buffer instead of direct mapped writes. No queue_wait_idle in the hot path.
</objective>

<locked_decisions>
- D-01: Create `StagingRing` in `src/renderer/staging_ring.rs` — a large CpuToGpu buffer (e.g., 32MB) divided into N regions (N = frame count = 2). Each frame uses its own region.
- D-02: `StagingRing::allocate(size: usize) -> StagingAllocation` returns an offset+mapped_ptr within the current frame's region. If the frame region is exhausted, flush and wait (rare, logged as warning).
- D-03: Fence-based reclamation: before writing to frame N's staging region, wait for frame N's in-flight fence (already waited in submit_frame). This guarantees the previous use of that region is complete.
- D-04: All 6 chunk pool buffers change from `MemoryLocation::CpuToGpu` to `MemoryLocation::GpuOnly`.
- D-05: `ChunkPool::record_uploads(cmd, staging_ring)` replaces `apply_upload` — it writes data to the staging ring and records `vkCmdCopyBuffer` from staging to GPU buffers.
- D-06: The old `write_allocation_bytes` function is removed or only retained for test/debug paths.
- D-07: `submit_one_shot_commands` (which uses queue_wait_idle) is NOT used for per-frame uploads. It may be retained for one-time initialization.
- D-08: The existing `StagingBuffer` in `staging.rs` is kept for egui texture uploads (those are infrequent). The new `StagingRing` is for per-frame chunk data.
- D-09: Add SAMPLED usage flag to depth image so it can be read for Hi-Z pyramid in 04-06.
- D-10: Staging ring size = 32 MB (configurable). With double buffering, each frame gets 16 MB. A full 881-chunk upload at max size would be ~28 MB, but that's a cold-start scenario; normal frame uploads are much smaller.
</locked_decisions>
</context>
