<locked_decisions>
- D-01: Push constant struct is `CameraUniforms { view_proj: Mat4, camera_pos: Vec3, _pad: f32 }` = 80 bytes, within the 128-byte minimum guarantee.
- D-02: Use `glam::Mat4::perspective_rh(fov_y, aspect, near, far)` for Vulkan RH [0,1] depth range.
- D-03: Use `glam::Mat4::look_at_rh(eye, target, up)` for the view matrix.
- D-04: FpsCamera stores position (Vec3), yaw (f32), pitch (f32), and computes forward/right/up vectors from yaw/pitch.
- D-05: The vertex shader push constant block replaces debug_project entirely: `gl_Position = camera.view_proj * vec4(world_position, 1.0)`.
- D-06: Dynamic viewport and scissor via VK_DYNAMIC_STATE_VIEWPORT + VK_DYNAMIC_STATE_SCISSOR. Pipeline no longer bakes viewport/scissor at creation time.
- D-07: Mouse input captured via winit's DeviceEvent::MouseMotion for delta-based look rotation. Cursor is confined/hidden when the window has focus.
- D-08: Front face stays CLOCKWISE (Phase 3 decision). Removing the Y-flip from debug_project means we now need to consider actual winding. Since perspective_rh produces standard Vulkan clip-space (Y-down = positive), and our vertex winding is CW in world space, CLOCKWISE front face remains correct.
- D-09: Default camera position at (32, 48, -60) looking toward the world center, matching roughly where content is.
- D-10: Push constants bound to VERTEX stage only since fragment shader doesn't need camera data.
</locked_decisions>
</context>
