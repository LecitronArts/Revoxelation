## Summary

Phase 2.5 replaces wgpu with raw Vulkan via `ash`. The project declares wgpu in Cargo.toml but has zero usage in `src/` — confirmed by the source glob, which shows no `renderer/` module exists. Migration is purely additive: remove Cargo entries, add new ones, build `src/renderer/`.

The two-plan split is correct. Plan 01 follows the mandatory Vulkan init sequence (instance → surface → device → swapchain → render pass → command pool → frame loop), which cannot be reordered. Plan 02 layers gpu-allocator and egui on top of Plan 01 resources and can begin once Plan 01 produces a clear-color window.

The dominant risk is **drop order**. Vulkan handles must be destroyed in exact reverse creation order; ash does not enforce this. The correct Rust pattern is one `Renderer` struct owning all handles with an explicit `Drop` impl. Splitting handles across independent statics with separate `Drop` impls causes non-deterministic destruction order and hard-to-diagnose crashes or validation errors.

**Primary recommendation:** One `Renderer` struct, explicit `Drop`, exposed via `OnceLock<Mutex<Renderer>>` matching the existing `STREAMING_STATE` pattern in `scheduler.rs`.

## Architecture Patterns

### Module Structure
```
src/renderer/
├── mod.rs           # pub struct Renderer; static RENDERER: OnceLock<Mutex<Renderer>>; pub fn submit_frame()
├── instance.rs      # create_instance(), setup_debug_messenger()
├── device.rs        # PhysicalDeviceInfo, select_physical_device(), create_logical_device()
├── swapchain.rs     # SwapchainState, create_swapchain(), recreate_swapchain()
├── frame.rs         # FrameData { command_buffer, sync: FrameSync }
└── egui_backend.rs  # EguiAshBackend, upload_textures(), record_egui_cmds()
```

### Pattern 1: Single-Owner Renderer with Explicit Drop
**Confidence:** HIGH — canonical ash idiom.
**Rule:** One struct owns every Vulkan handle. `Drop` calls `device_wait_idle()` first, then destroys handles in strict reverse creation order. Use `ManuallyDrop<Allocator>` so the allocator is freed before the device.

Creation order (and reverse-destruction order):
1. `ash::Entry` — no destroy needed
2. `ash::Instance` → `destroy_instance(None)`
3. Debug messenger → `destroy_debug_utils_messenger`
4. `VkSurfaceKHR` → `destroy_surface`
5. `ash::Device` → `destroy_device(None)` (after everything below)
6. Queues — not explicitly destroyed
7. `VkCommandPool` → `destroy_command_pool`
8. `gpu_allocator::vulkan::Allocator` (ManuallyDrop) → drop before device
9. `VkSwapchainKHR` → `destroy_swapchain`
10. `VkRenderPass` → `destroy_render_pass`
11. `VkFramebuffer[]` → `destroy_framebuffer` each
12. `FrameData[2]` — `destroy_semaphore`, `destroy_fence` each
13. `EguiAshBackend` — pipeline, descriptor pool, atlas image/view/sampler

### Pattern 2: Per-Frame-in-Flight Resources
**Confidence:** HIGH — standard double-buffering.

```rust
pub struct FrameSync {
    pub image_available: vk::Semaphore,
    pub render_finished: vk::Semaphore,
    pub in_flight:       vk::Fence,     // create with SIGNALED flag
}
pub struct FrameData {
    pub command_buffer: vk::CommandBuffer,
    pub sync: FrameSync,
}
// Select slot: (frame_index % 2) as usize
```

### Pattern 3: Frame Loop
**Confidence:** HIGH.

Ordering invariant: wait-for-fence → acquire → reset-fence → record → submit → present.
Reset fence AFTER acquire (not before) — acquiring may block, and resetting before means the fence could be unsignaled with no work in flight.

```rust
pub fn submit_frame(r: &mut Renderer, frame_index: u64) -> anyhow::Result<()> {
    let fi = (frame_index % 2) as usize;
    let sync = &r.frames[fi].sync;
    unsafe {
        r.device.wait_for_fences(&[sync.in_flight], true, u64::MAX)?;
        let (img_idx, _) = r.swapchain_loader.acquire_next_image(
            r.swapchain, u64::MAX, sync.image_available, vk::Fence::null())? ;
        r.device.reset_fences(&[sync.in_flight])?;
        // record r.frames[fi].command_buffer here
        r.device.queue_submit(r.graphics_queue, &[vk::SubmitInfo::builder()
            .wait_semaphores(&[sync.image_available])
            .wait_dst_stage_mask(&[vk::PipelineStageFlags::COLOR_ATTACHMENT_OUTPUT])
            .command_buffers(&[r.frames[fi].command_buffer])
            .signal_semaphores(&[sync.render_finished]).build()],
            sync.in_flight)?;
        r.swapchain_loader.queue_present(r.present_queue,
            &vk::PresentInfoKHR::builder()
                .wait_semaphores(&[sync.render_finished])
                .swapchains(&[r.swapchain])
                .image_indices(&[img_idx]).build())?;
    }
    Ok(())
}
```

### Anti-Patterns to Avoid
- **Module-level statics per subsystem:** `static INSTANCE`, `static DEVICE` in separate modules will drop in non-deterministic order. Use one struct.
- **Forgetting `device_wait_idle()` in Drop:** Destroying resources while GPU is still using them triggers validation errors and crashes.
- **Resetting fence before acquire:** Deadlock risk if acquire blocks and the fence was the only sync primitive tracking that frame.
- **Not using `ManuallyDrop` for allocator:** If allocator is a regular field it drops after `device` (Rust field drop order is declaration order), but gpu-allocator must be freed before device. Use ManuallyDrop and call ManuallyDrop::drop explicitly in Drop before destroy_device.
- **Allocating per-buffer without sub-allocator:** Calling vkAllocateMemory for every buffer hits the ~4096 implementation limit. Use gpu-allocator for all buffer memory.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|

| Swapchain format selection | Hardcode BGRA8_UNORM | Query get_physical_device_surface_formats | Format availability varies by driver; prefer SRGB if available |
| Validation callback | fprintf to stderr | Route through log::error! | Integrates with existing env_logger setup |

## Common Pitfalls

### Pitfall 1: Wrong Drop Order
**What goes wrong:** Validation errors object-destroyed-while-in-use or silent crash on exit.
**Why it happens:** Rust drops struct fields in declaration order; Device is not last if declared first.
**How to avoid:** Explicit Drop impl. Call device_wait_idle() first. Destroy in reverse creation order. Use ManuallyDrop for allocator.
**Warning signs:** VUID-vkDestroyDevice-device-00378 in validation output.

### Pitfall 2: Swapchain Recreation on Resize
**What goes wrong:** VK_ERROR_OUT_OF_DATE_KHR from acquire_next_image or queue_present; crash or hang.
**Why it happens:** Swapchain extent must match window size.
**How to avoid:** Handle ERROR_OUT_OF_DATE_KHR and SUBOPTIMAL_KHR from both acquire and present. Call recreate_swapchain() which device_wait_idle()s then destroys old framebuffers/swapchain and rebuilds.
**Warning signs:** Validation VUID-VkSwapchainCreateInfoKHR-imageExtent on resize.

### Pitfall 3: Forgetting to Reset Command Buffer
**What goes wrong:** Commands accumulate across frames; undefined behavior or validation errors.
**How to avoid:** Create pool with RESET_COMMAND_BUFFER flag. Call reset_command_buffer at start of each frame record phase.

### Pitfall 4: gpu-allocator Drop Before Device
**What goes wrong:** Assertion or use-after-free in allocator destructor.
**How to avoid:** ManuallyDrop::drop(&mut self.allocator) before self.device.destroy_device(None) in Drop.

### Pitfall 5: Queue Family Index Mismatch
**What goes wrong:** Validation error on submit or present fails silently.
**How to avoid:** Require single queue family supporting both GRAPHICS flag and surface support. Acceptable constraint for Phase 2.5 target hardware.

### Pitfall 6: egui Atlas Texture Format
**What goes wrong:** Font renders as white rectangles.
**Why it happens:** egui font atlas is R8_UNORM (single channel).
**How to avoid:** Create atlas as VK_FORMAT_R8_UNORM. In fragment shader: out_color = vec4(1,1,1, texture(atlas,uv).r) * vertex_color.

### Pitfall 7: winit Event Loop Ownership
**What goes wrong:** Renderer creation conflicts with EventLoop ownership on Windows.
**How to avoid:** Initialize OnceLock<Mutex<Renderer>> inside EventLoop::run() closure on first RedrawRequested. Use MainEventsCleared to call window.request_redraw().

### Instance Creation with Conditional Validation (HIGH confidence)
```rust
pub fn create_instance(
    entry: &ash::Entry,
    window: &winit::window::Window,
) -> anyhow::Result<ash::Instance> {
    let app_info = vk::ApplicationInfo::builder()
        .application_name(c"Revoxelation")
        .api_version(vk::API_VERSION_1_3);
    let mut exts =
        ash_window::enumerate_required_extensions(window.raw_display_handle())?.to_vec();
    #[cfg(debug_assertions)]
    exts.push(ash::extensions::ext::DebugUtils::name().as_ptr());
    let layers = if cfg!(debug_assertions) {
        vec![c"VK_LAYER_KHRONOS_validation".as_ptr()]
    } else {
        vec![]
    };
    let info = vk::InstanceCreateInfo::builder()
        .application_info(&app_info)
        .enabled_extension_names(&exts)
        .enabled_layer_names(&layers);
    Ok(unsafe { entry.create_instance(&info, None)? })
}
```

### egui-ash Backend Minimal Contract (MEDIUM confidence)
Each frame the backend must:
1. Process TexturesDelta.set: upload new/updated atlas tiles to VkImage (R8_UNORM)
2. Process TexturesDelta.free: destroy freed images
3. Per ClippedPrimitive Mesh: write verts+indices to staging, copy to device-local, set scissor from clip_rect, draw with screen_size push constant
4. Fragment shader reads font alpha as .r channel: `out_color = vec4(1,1,1, texture(atlas,uv).r) * v_color`
