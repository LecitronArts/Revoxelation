**gpu-allocator staging buffer lifecycle and a minimal egui-ash backend wired into the Renderer for Phase 3 mesh uploads and HUD overlay rendering**

## Accomplishments
- Extended `Renderer` with `ManuallyDrop<Allocator>` and confirmed correct drop order (allocator freed before `destroy_device`).
- Implemented `StagingBuffer` (new/write/copy_to/copy_to_image/destroy) plus reusable helpers for allocated buffer/image lifecycle and one-shot commands — the upload primitives Phase 3 meshing needs.
- Created `EguiAshBackend` with font atlas upload via `StagingBuffer`, descriptor set management, and a scratch-buffer mesh path ready for push-constant-based HUD draw calls.

- `tests/phase25_vulkan.rs` — adds `staging_buffer_api_compiles` and `egui_backend_type_compiles` stubs (4 stubs total, all passing)

## Decisions Made
- Used scratch (allocate + free each paint call) GPU buffers for vertex/index data rather than persistent per-frame buffers. Acceptable overhead for a debug HUD; Phase 3 will introduce a persistent upload ring buffer for geometry.
- Font atlas format is `R8G8B8A8_SRGB` to match egui's sRGB output from `srgba_pixels(None)`. The research doc mentioned `R8_UNORM` but egui's `FontImage` already converts to sRGBA before the backend receives it.
- `StagingBuffer::copy_to_image` placed on `StagingBuffer` itself (not `EguiAshBackend`) so Phase 3 can reuse the same upload path for chunk texture data.
