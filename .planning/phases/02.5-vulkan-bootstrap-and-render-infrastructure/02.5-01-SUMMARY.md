# Phase 02.5 Plan 01: Vulkan Bootstrap Summary

**ash-based Vulkan bootstrap with swapchain/render-pass/frame-loop scaffolding and scheduler submit wiring**

## Accomplishments
- Replaced the dormant `wgpu` dependency set with `ash`, `ash-window`, `gpu-allocator`, and `raw-window-handle`.
- Added `src/renderer/` with instance creation, device selection, swapchain/render pass setup, frame resources, and a clear-color `submit_frame()` path.
- Wired `Stage::RenderSubmit` to call the renderer submit path only when a renderer has actually been installed, preserving the current runtime's no-window execution path.
- Added headless compile-check tests for the renderer public API surface.

## Files Created/Modified
- `Cargo.toml` - swaps rendering dependencies to Vulkan-native crates.
- `Cargo.lock` - captures the resolved Vulkan dependency graph.
- `src/lib.rs` - exports the new renderer module.
- `src/runtime/scheduler.rs` - hands RenderSubmit to the renderer when initialized.
- `src/renderer/mod.rs` - owns renderer state, global access, submit path, and explicit teardown.
- `src/renderer/instance.rs` - creates the Vulkan instance and debug messenger.
- `src/renderer/device.rs` - chooses the physical device and logical queues.
- `src/renderer/swapchain.rs` - creates swapchain images, image views, render pass, and framebuffers.
- `src/renderer/frame.rs` - allocates per-frame command buffers and sync primitives.
- `tests/phase25_vulkan.rs` - compile-only renderer API guards.

## Decisions Made
- Kept the global renderer accessor optional so the existing `run_frame(0)` bootstrap can continue to execute before a Vulkan window/init path exists.
- Corrected the plan's crate-version combination to a compatible set (`ash-window 0.13` with `ash 0.38`) after the original pairing failed on real compilation.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Fixed ash-window and raw-window-handle version compatibility**
- **Found during:** Task 1 (Update Cargo.toml, scaffold renderer files, and wire scheduler)
- **Issue:** `ash-window = 0.12` pulled `ash 0.37`, which made surface creation types incompatible with the plan's required `ash 0.38`.
- **Fix:** Updated dependencies to `ash-window = 0.13` and `raw-window-handle = 0.6`, then re-ran the compile checks against the real crate graph.
- **Files modified:** `Cargo.toml`, `Cargo.lock`
- **Verification:** `cargo test --test phase25_vulkan`, `cargo build`
- **Committed in:** `0f79198`

**2. [Rule 1 - Bug] Prevented RenderSubmit from panicking before renderer initialization exists**
- **Found during:** Task 1 (Update Cargo.toml, scaffold renderer files, and wire scheduler)
- **Issue:** The planned `renderer_state().expect(...)` access would panic immediately because the current app never installs a renderer yet.
- **Fix:** Changed the renderer accessor to return `Option<&Mutex<Renderer>>` and guarded the scheduler handoff so the runtime stays safe until a real window/init path lands.
- **Files modified:** `src/renderer/mod.rs`, `src/runtime/scheduler.rs`
- **Verification:** `cargo build`, `cargo test --test phase25_vulkan`
- **Committed in:** `0f79198`
