# Phase 2.5 Context: Vulkan Bootstrap and Render Infrastructure

*Context gathered: 2026-03-21*

## Phase Goal

用原生 Vulkan（ash crate）替换 wgpu 依赖，建立 gpu-allocator 管理的 staging buffer 流水线和 egui-ash UI 集成，为 Phase 3 贪心网格渲染提供稳固底层基础。

**插入原因**: 用户需要更深层的性能控制——精确管控内存分配、transfer queue、render pass 结构。Phase 2 之后 src/ 内无任何实际渲染代码，此时切换代价接近零。

## Decisions

### 渲染 API 选择

- **目标**: 移除 wgpu，改用 ash（Vulkan 原生 Rust 绑定）
- **原因**: 大世界 LOD 流式场景需要精确控制 staging buffer、transfer queue 和内存池
- **wgpu 现状**: Cargo.toml 中声明但 src/ 内零实际使用——切换无返工成本
- **ash 版本**: 使用最新稳定版（与 Vulkan SDK 1.3+ 对齐）

### GPU 内存管理

- **策略**: 使用 `gpu-allocator`（Rust 原生，Intel/AMD/NVIDIA 均支持）
- **不用**: 手动 `vkAllocateMemory` / `vkFreeMemory`——过于底层，Phase 2.5 范围内不值得
- **分配模式**: linear allocator 用于 staging，GPU-local pool 用于 vertex/index buffer
- **目标**: Phase 3 网格上传路径通过 gpu-allocator 分配 staging buffer，复制到 device-local

### egui 集成

- **保留 egui**: 是——调试 HUD 是必要的（帧率、区块状态可视化）
- **后端**: 手写 egui-ash 集成（egui 提供 `egui-wgpu` 参考实现，按相同接口适配 ash）
- **范围**: Phase 2.5 Plan 02 实现最小可用的 egui-ash 后端——能渲染 egui `TexturesDelta` 和 `ClippedPrimitive`
- **不做**: 完整的 egui 功能兼容——只需 HUD overlay 能工作

### Vulkan Bootstrap 范围

- **Plan 01 覆盖**: instance + validation layers + physical/logical device + swapchain + render pass + command pool + frame loop（acquire→render→present）
- **Plan 02 覆盖**: gpu-allocator 初始化 + staging buffer 抽象 + egui-ash 集成
- **不做（留 Phase 3）**: vertex buffer 格式、mesh pipeline、descriptor sets for world geometry
- **同步模型**: 双缓冲帧（2 frames in flight），每帧独立 command buffer 和 semaphore
- **Validation**: debug build 开启 `VK_LAYER_KHRONOS_validation`，release build 关闭

```toml
egui-ash = { git = ... } # 或手写集成模块
```

### 与现有基础设施集成

- `src/runtime/stages.rs` Stage 枚举不变——RenderSubmit 阶段调用 Vulkan present
- `src/runtime/scheduler.rs` RenderSubmit arm 调用新的 `vk_renderer::submit_frame()`
- `src/runtime/observability/hud.rs` 通过 egui-ash 后端渲染
- streaming 子系统不受影响——ChunkJobResult 仍通过 mpsc 传递原始体素数据

### 平台目标

- Windows + Linux 优先（Vulkan 1.3+）
- MoltenVK / macOS 不在 v1 范围内
